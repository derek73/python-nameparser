# R1 — fields are views of the parsed words

## Standing

- One comma segment is one suffix entry, and the boundary between entries is the comma the writer typed: two consecutive post-nominals are one entry where they sit in the same comma bucket, `comma_bucket` being the function the segments are built with, and nothing between them parts the run (`Smith, MD PhD` and `John Smith MD PhD` → suffix 'MD PhD', `John Smith, MD, Bart` → 'MD, Bart', `Smith Jr., Mr. Jr.` → 'Jr., Jr.') — 2026-09-06 #436/#437.
- A name word or a dropped delimiter core parts a run, and a token whose role renders into another field (title, nickname or maiden) or a dropped token that is no core does not (`Smith, MD Dr. PhD`, `Smith, MD "Doc" PhD` and `Smith, MD (nee Jones) PhD` → suffix 'MD PhD'); the core set is `delimiter_cores`, the derivation group's drop site reads, imported rather than repeated — 2026-09-06 #436/#437.
- The parting scan reads the core set whole, by text, ungated by the tail segment group drops cores on, so a dropped token whose text the policy names parts the run whatever dropped it (`Smith, MD (nee Jones) PhD` → 'MD PhD' by default and 'MD, PhD' under `extra_suffix_delimiters=frozenset({" nee "})`); the pass runs after roles are settled, since the span rule read role-blind would join two middle names, and last in post_rules by convention rather than necessity — 2026-10-19 #760.
- Within a piece the `joined` tag renders a merged piece as one unit whatever role it holds, so `Smith, Rev. Dr.` keeps `title_list == ['Rev.', 'Dr.']` and a `Ph. D.` merge stays one unit in any field; a role-aware tag, a render-time span scan, marking the boundary at the core-drop site and a third branch in group beside `tail` were declined — 2026-08-23 #429; 2026-09-06 #436/#437.
- Group still drops a delimiter core only on a tail segment, v1 `expand_suffix_delimiter` parity (#206) — 2026-08-23 #429; 2026-09-06 #436/#437.
- `str()` is a rendering, not a canonical form: a suffix run survives a render and a reparse on the three writings #429 fixed (`test_a_suffix_run_survives_a_render_and_a_reparse`), and no rule promises a general round trip — 2026-09-06 #436/#437.
- A suffix value handed to `revise()` derives its entries from its own commas by the rule a whole name uses, `revise` forcing the role and re-running `suffix_entries` over the forced state, so `revise(n, suffix=n.suffix)` keeps 'MD PhD' for `John Smith MD PhD`; the value is classified on its own, so `김민준씨, J.씨` revises its suffix '씨, J.씨' to '씨, J. 씨', and a policy delimiter parts a value only where its own words give it a tail segment (under `extra_suffix_delimiters=frozenset({" - "})`, `Doe, John, MD PhD - FACS` reads 'MD PhD, FACS' and `revise` with 'MD PhD - FACS' keeps it whole) — 2026-09-06 #511.
- `revise` keeps the sub-parse's tags minus FOLDED_TAG, so a within-piece mark survives (`revise(n, family="John Ph. D. Smith")` keeps 'D.' marked `joined`) and a between-piece suffix mark left on a forced non-suffix role is a tag-only oddity left as it is; a list-valued `revise` and a text-only delimiter read inside it were declined, and `replace(suffix="MD, PhD")` rendering 'MD,, PhD' is left as is, `replace` whitespace-splitting by contract — 2026-09-06 #511.
