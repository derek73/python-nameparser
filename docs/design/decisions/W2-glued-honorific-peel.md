# W2 — the glued-honorific peel

## Standing

- A glued entry peels only where it can never end a name, the vocabulary carrying the license with no structural or per-script gate: `田中さん` → family '田中', suffix 'さん' and `김민준씨` → suffix '씨', while 양, 군, 氏, 博士 and 殿 are spaced-only (`김지양` → given '지양', `田中殿` → family '田中殿') and 君 is in neither set though くん peels (`王君` → family '王君', `田中くん` → suffix 'くん') — 2026-08 #308.
- The peel crosses the 间隔号, which still stops the surname split beside it: `马丁·路德·金씨` → family '金', suffix '씨' — 2026-08 #312.
- A wholly suffix-shaped part after a family comma is declined as the peel's site only where the part before it offers a site of its own: under the default policy `田中さん, V.` peels before the comma (family '田中', given 'V.', suffix 'さん') and `이, J.씨` is scanned anyway (given 'J.', suffix '씨') — 2026-08 #319. Both are comma forms, which rules/W3 describes rather than promises (Elsewhere below).
- The #671 credential, office and generational words are suffix words spaced and after a comma, and all but 部長/部长 peel glued: `田中 部長` → suffix '部長' while `田中部長` stays family '田中部長', and `田中社長` → suffix '社長', `陳怡君二世` → family '陳怡君', suffix '二世' — 2026-10-17 #671; 2026-10-17 #707.
- After a listed surname under `locales.ZH` the division leaves such a word as a whole token, which reads as a suffix word: `王二世` → family '王', suffix '二世', `李部長` → family '李', suffix '部長' — 2026-10-17 #671.
- 小 as "Jr." (written before the name, and a common given-name character) is kept out of the suffix words, and 冯/馮 as "von" (a top-30 surname) out of the particles — 2026-10-17 #671.
- The peel takes one word: `王雅婷婷婷二世議員` → family '王雅婷婷婷二世', suffix '議員' — 2026-10-17 #707.
- Accepted: an unlisted compound office or degree word splits at its listed tail, spaced or glued (`田中 副社長` → given '副', suffix '社長'; `岸田文雄衆議院議員` → family '岸田文雄衆議院', suffix '議員'), the older `김민준의학박사` → given '민준의학', suffix '박사' with them — 2026-10-17 #707.
- The spaced and glued bars differ, an entry being safe spaced and unsafe glued but never the reverse; a CJK entry is self-selecting; and kana is no license by itself, hiragana spelling Japanese given names (`高橋 みなみ` → given 'みなみ'), so the kana honorifics were vetted one at a time — 2026-10-18.
- Only a family comma brings a second run into the scan, being the one structure that splits the name itself: a post-nominal inside the one run is stepped over (`김민준씨 Jr.` → family '김', suffix '씨 Jr.'), a part past the second run is never reached (`Dr 김민준씨, Jr., 박씨` → suffix '씨, Jr., 박씨'), and the scan reads segments rather than tokens, so a nickname is no site (`김민준씨 (Jimmy)` → suffix '씨', nickname 'Jimmy') — 2026-10-19 #760.

Elsewhere: a post-nominal word standing on its own is never the name's end and never dissected (`김민준 박사님` → suffix '박사님', `선생님` → family '선생님'), decisions/cjk-comma-demotion's 2026-09-05 entry that restored it to W2; the family-comma crossing is tolerated input, that file's 2026-09-01 #469 entries and rules/W3; a full stop glued to the honorific rides with it (`김민준씨.` → suffix '씨.'), decisions/cjk-full-stops' 2026-09-10 #322/#323 line; 二世's generational reading, and #707's peel reversing #679's refusal of it, decisions/generational-words' 2026-10-21 #762 entry; the peel asks the comma's own decision rather than a copy of it, decisions/C1's 2026-10-06 (Derek), #613 entry.

Open: none in this file.

WHY ONLY THE FAMILY COMMA CROSSES: a comma is how a writer says which runs are the name, and a family comma is the one structure that splits the name itself across two of them (`김, 민준씨` is runs (0,) and (1,)), with the honorific as often glued to the given side as to the family. Every other structure keeps the whole name in segments[0], so the asymmetry is the point rather than an accident of two cases. "The rest is post-nominals" is true of the SUFFIX comma only: under NO_COMMA segment returns one run and a trailing post-nominal is INSIDE it (`김민준씨 Jr.` is one run of two tokens, family '김', suffix '씨 Jr.'), which is why the scan-back steps over such a token rather than never reaching it. WHY THE RUN PREDICATE IS ASKED: the structure says nothing about whether segments[1] is name text — segment hands every comma form over as FAMILY_COMMA (#613), and a one-word part turned a wholly suffix-shaped remainder into FAMILY_COMMA anyway (`田中さん, V.`). THE SCOPE HOLDS OFF A JUNK TAIL past the second run: `Dr 김민준씨, Jr., 박씨` is a postnominal part behind a whole name (`_postnominal_behind_a_whole_name`), so the scan stays in segments[0] and 박씨 in a third run is never reached (family '김', suffix '씨, Jr., 박씨'). AN EMPTY SECOND RUN stays in scope and contributes nothing: `is_wholly_suffix` is False on it by its own contract (v1 read `Doe,, Jr.` as a family comma), which is the reading the peel wants, flattening an empty run adding no site. FLATTENING SEGMENTS, NOT `state.tokens`, is load-bearing: extracted nickname and maiden content is in tokens but in no segment, and scanning tokens would put the site on a nickname (`김민준씨 (Jimmy)` would peel nothing); the case row `ko_honorific_glued_given_nickname` pins it (family '김', given '민준', suffix '씨', nickname 'Jimmy'). WHY THE PREDICATE IS CIRCULAR HERE ALONE, and so needs the second condition: not because `_comma.decide` asks it too (at group's head, after this stage), but because decide SPENDS the answer differently — it reads the run's shape and stops, the answer being the structure, while the peel reads the same shape and then decides whether to strip the very honorific that produced it. Declining a run that holds the only site does not fall back to another site; it loses the peel outright, and with it the given name, which lands in suffix (`이, J.씨` would read suffix 'J.씨').
