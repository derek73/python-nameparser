# O8 — letters ending a name as its family

## Standing

- The default reading of letters ending a name does not change: `Lakshmi R S` keeps middle `R`, family `S` — 2026-11-11 #1254.
- Reading the letters as the family is an opt-in `Policy` switch, `initials_as_family`, off by default, which a pack's `[rules]` may turn on (`initials_as_family = true`): given-first, it is the same string shape as a middle and a family initial and as a byline written surname first — 2026-11-11 #1254.
- The switch reads two or more letters in a row, each in the shape rules/T5 reads as an initial, ending the name words, under the given-first order, with no family comma and a name word before them; one letter, letters before or inside the name and a name read family-first are left as they are — 2026-11-11 #1254.
- No byline value: `name_order=FAMILY_FIRST` stays the setting for a bibliography written surname first, since no list's own names can select such a value safely — 2026-11-11 #1254.
- `locales.NE` turns the switch on; no other pack does — 2026-11-11 #1254.
- The switch reports nothing — 2026-11-11 #1254.

## Log

- **2026-11-11 #1254 — LETTERS ENDING A NAME ARE ITS FAMILY ONLY WHERE THE CALLER, A PACK OR THE GROUP SUGGESTER SAYS SO.** #1163 asked whether `Lakshmi R S` should read family `R S` by default, citing 538 ORCID records whose family box held the letters against 0 holding the word before them. That count could not decide it: ORCID's `name` field is composed as the given box then the family box (`tools/differential/local_orcid.py`), so the word before the letters can never be the family there; the count reproduces exactly from that field (539 to 0). Measured instead on text the writer typed whole, with throwaway scripts against the local corpora, on master 5a072056 (fetched: orcid-researchers 2026-10-27, ctgov-officials 2026-10-21, nepal-candidates 2026-10-24, tse-donors 2026-10-22, opensanctions-parliaments 2026-11-08, patentsview-inventors 2026-10-28). The scripts are in the 3.1 cycle's session notes, not the repository, so these counts cannot be re-run from the tree; they are dated snapshots. A name ending in a spaced run of two or more letters falls in one of three classes: the letters are the family (the switch fixes it), a middle and a family initial (`Melanie J D`, the switch breaks it), or a byline whose first word is the family (wrong either way).
  - ORCID credit names, against the holder's boxes, with the unclear ones read by hand: 66 letters-the-family, 11 middle-and-family, 302 bylines, 24 unknown, of 403.
  - ClinicalTrials.gov officials, all 55 read by hand: 18, 8, 26 (three neither).
  - Nepal's candidates: 622, all letters-the-family, checked against the Devanagari written beside each (`बि.क.`, `वि क`, or the full `विश्वकर्मा`); 547 of the runs are `B K`, 89 `K C`.
  - Brazil's TSE donors, against each registry name: 75 middle-and-family, none letters-the-family, 223 truncated past telling.
  - ORCID's and PatentsView's composed fields cannot show a byline but do split the other two: 536 to 22 and 113 to 32, the middle-and-family rows mostly Indian filers splitting the same letters across the boxes.
  - So spacing does not separate the conventions, and a default change trades one population for another: no default change, an opt-in switch, the fork reported (#1137).
  - `locales.NE` against nepal-candidates, re-run from the tree with `uv run python tools/differential/config_diff.py diff --local nepal-candidates "plain:NE@initials_as_family=0" "plain:NE"` (2026-11-11): 552 of the corpus's 237,408 spellings move, every one from middle to family, 551 romanized names and one Devanagari name written with dotted initials (`झलक बहादुर आ. म.`). Read against the Devanagari beside each romanized name with a throwaway script (session notes): 508 write the same letters, 23 write them joined, with joiners or with commas, and 20 write the surname in full (`विश्वकर्मा`, `केसी`) or add a clan name in brackets (`के सी (महर्जन)`), two of them another surname of the same group (`Mani B K` as `सिरपाली`, `Tilsara Sunar B K` as `सुनार`).
  - With the switch off, nothing moves: the committed snapshot changed only by this rule's 27 example names new to the rules corpus, and `snapshot.py --local <source> --base <a checkout of 62bbdeb1>` matched the base for nepal-candidates, ctgov-officials, tse-donors, jrc-names, psc-individuals, orcid-researchers, patentsview-inventors and fec-individuals; opensanctions-parliaments was not read (its cache predates six of the datasets the tool reads, and a fetch would rewrite the shared cache).
  - Other packs, not turned on: no other population held supports it. India's Lok Sabha (opensanctions `in_sansad`, the `hi` pack's nearest population) ends 14 of 8,295 names in a spaced run, every one a South Indian name with the letters as the family (`Matheswaran V S`, `Kochunni M C`), which the `hi` pack's Hindi-writing population does not write; ORCID's credit names from India hold 40, 22 letters-the-family, 7 bylines, 2 middle-and-family, 9 unknown. Tamil, Kannada, Malayalam and Telugu packs, which do not exist, are where the switch would belong.
