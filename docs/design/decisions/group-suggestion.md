# group-suggestion — settings suggested by a group of names

## Standing

- The parser never detects language; the group suggester (`Parser.suggest`) may, over a group the caller declares, says what it saw, and its answer is configuration the caller applies; the parse itself is untouched by it — 2026-11-10 SCOPE.
- The two word tables the suggester reads (romanized zh, ko and vi surnames; common given names) are private compiled tables for the first version, not `Lexicon` kinds: no parse reads them, a language choice or `strict=True` does not filter them and a caller cannot edit them — 2026-11-10 TABLES.
- The given-name table is derived from ORCID's public data file (CC0), per stated country the words its holders most often typed first in the given-name box, replacing the derivation from nam_dict (GNU FDL 1.2, which seeded the shipped familiar forms until decisions/name-matching's 2026-11-12 ENGLISH ONLY UNTIL REBUILT) approved on 2026-11-10 and in no release — 2026-11-12 GIVEN NAMES FROM ORCID.
- The given-name table's size and the rest of its filter (the top 500 per country, each typed first in the given-name box at least 3 times there, at least 20 uses, no full stop, no word the default lexicon reads as a title outside `titles_ambiguous`) and the hand-kept surname lists — 2026-11-10 TABLES, 2026-11-12 GIVEN NAMES FROM ORCID.
- The given-name table keeps a name written in ORCID's family box in at most 10% of its uses, and refuses every word the default lexicon lists as a suffix, the ones that may also be a name included, and every title it lists as an abbreviation — 2026-11-15 #1357.
- No surname table beyond the romanized zh, ko and vi one for 3.1; #1364 stays open for 3.2 — 2026-11-15 #1357.
- What `suggest` decides for a group is one release's answer, not a promise across releases: the tables and thresholds are tuned between them, so a caller keeps the settings applied (the patch, or the `Policy` it made) with the data; nothing promises that a later release suggests the same settings for the same names — 2026-11-15 ACROSS RELEASES.
- The evidence declined (the vocabulary's name readings, `Reading.languages`, the familiar forms) — 2026-11-10 DECLINED.
- A comma name states its own order and does not vote on order — 2026-11-10 SIGNALS.
- An East Slavic group gets the patronymic rule with a given-first order, since the rule reads either written order one name at a time and reorders none under a declared family-first order, unless the names' own order votes decide family-first, which the rule never overrides, or the next line keeps a `FAMILY_FIRST` base's order — 2026-11-10 SIGNALS, 2026-11-10 FIX WAVE.
- Where the East Slavic rule is decided under a `FAMILY_FIRST` base and the names' own votes do not decide given-first, the suggestion keeps the base's order and suggests the rule alone if more of the names carrying the patronymic write it last (family, given, patronymic) than in the middle (given, patronymic, family); a tie, a middle majority, a `FAMILY_FIRST_GIVEN_LAST` base and a given-first base get the given-first order with the rule, as before; a base already carrying the rule keeps its rule value on every branch — 2026-11-15 #1356.
- A list mixing East Slavic and Turkic patronymics is left as it is for 3.1: one patronymic decision is made for the list, by the thresholds, so the larger set's rule where it clears them and none where neither does — 2026-11-15 #1356.
- A patronymic votes only where the pipeline's rule reads one (rules/O1's three name words, rules/O2's four, and since 2026-11-12 #1187 its three with the marker last), a name is read past its listed titles and post-nominals, and a comma followed by post-nominals alone reads the name before it — 2026-11-10 FIX WAVE.
- An order is decided by at least two names, more than two thirds of the names casting an order vote and at least 1% of the group's names; a patronymic rule by at least five names carrying it and more than four in five of the names casting any vote; otherwise the base stands — 2026-11-10 THRESHOLDS, 2026-11-16 ORDER FLOOR.
- Where any name casts a trailing-initial vote, the votes are cast only where at least three names, and at least 60% of the group's names holding a name word, end in initials no other signal in the same name contradicts; elsewhere every one is set aside, a contested one included (60% kept after a curve of lower shares and a minimum of 2 names, each declined), the order evidence's note says how many names end so, and the patronymic evidence's note how many names whose only vote was set aside still count in its share — 2026-11-11 TRAILING INITIAL.
- `initials_as_family` (rules/O8) is turned on where one run of letters ends at least two of the group's names and at least half of the names ending in a run, a spaced run counted where the rule moves it and a run joined with full stops (`B.K.`) counted beside it; a group decided so casts no trailing-initial vote on its order; a group never turns the switch off, and a base reading names family first decides nothing — 2026-11-11 LETTER RUNS.

- `capitals_as_family` (rules/O9) is turned on where at least two names, and more than two thirds of the names with evidence either way, write the family in capitals: a name counts for it where the rule, asked of the parse with the switch on, reads as its family a word in capitals of four letters or more that the lexicon lists as no credential or numeral and that the base, parsing the name, does not read as a title; against it where the switch would move its family onto words the base reads as titles, and where it is two words or more holding an uppercase and a lowercase letter with no word in capitals; two or three capitals and a name in one case are no evidence; a name against a decided switch disagrees; a group never turns it off, a base reading unlisted capitals as credentials everywhere decides nothing, and the order vote is untouched — 2026-11-12 CAPITALS.
- A capitals word of two or three letters opening a name that holds a lowercase letter (`AM Hoy`, joined initials; `NG Emily`, a short surname) casts no capitals vote, and a name opening in one casts no surname vote; no group gate — 2026-11-14 #1355.
- A capitals word of two or three letters ending a name that holds a lowercase letter casts no surname vote of its own, and where it is itself a listed surname (`Zhou NG`) the name casts no surname vote; otherwise the word in front votes as before; its capitals vote stays silent — 2026-11-14 #1397.
- That rule's reach as implemented, the opening word standing alone: a run of capitals words in front votes as before, whatever its first word (`DE SOUZA Maria`) — 2026-11-14 #1355.
- A name word in a script that writes no initials followed by a letter of it casts no trailing-initial vote, since no byline writes such a name before an initial, as rules/T5 and the order report read it: a group of Thai or Burmese names, each a word and a letter, suggests nothing — 2026-11-12 #1256.
- A caller with a large list is told a sample of a few hundred names from each source is enough: nearly every kind of list measured is read right from 200 names, a longer list is rarely better (bylines written given first under a family-first base are the one kind measured that kept improving), and since the 1% floor no list measured in its base's own order is read worse at 2,000 names — 2026-11-16 #1442, 2026-11-16 ORDER FLOOR.

Open: the other three settings count their shares among the names with evidence on them, never the group, so a few stray names decide `patronymic_rules`, `initials_as_family` or `capitals_as_family` in a long silent list (2026-11-16 ORDER FLOOR, its bullet on the other settings); no measured population moves on any of them, and no issue is filed. A group gate for the short capitals words, under which one votes where another name of the list writes a longer capitals word at the same end, measured and not taken for 3.1 (2026-11-14 #1355, its Declined bullet), to weigh beside #1402. For a list mixing East Slavic and Turkic patronymics (uz_senate, kz_senate), suggesting both rules, and reading the Kazakh `-uly` and `-kyzy` endings as a Turkic signal, are not taken for 3.1 and not decided against (2026-11-15 #1356, its Not taken bullet). `_MIN_PATRONYMIC_VOTES`, five names, was set to keep small Russian groups written family first from moving a family-first base to given-first (2026-11-10 THRESHOLDS); since 2026-11-15 #1356 a `FAMILY_FIRST` base keeps its order on such a group, and that entry measured what relaxing the count does now: no same-order cell moves, and groups written given-first move a family-first base sooner. The threshold is unchanged and has no issue. #1308, the tracking issue, is closed; its other open item, the given names the given-name table's family-share filter drops, was #1357, settled for `John`, `David` and `Robert` by 2026-11-15 #1357, which leaves `James`, `Paul`, `George`, `Charles`, `Thomas` and `Martin` out. #1364, a surname table for names outside zh, ko and vi, is open for 3.2: 2026-11-15 #1357 holds what a gate measured for it (a dated snapshot), the cost no population of the tool shows (a list whose given names are listed surnames) and the sources no entry of decisions/shipped-data-licences clears. - **2026-11-10 SCOPE — THE NEVER-DETECT-LANGUAGE RULE IS ABOUT THE PARSE, AND THE GROUP SUGGESTER IS OUTSIDE IT (DECIDED BY 2026-11-15 ACCEPTED).** AGENTS.md's design philosophy says the parser never detects language, because the language of a Latin-script name cannot be read off the name. `Parser.suggest` works on a group the caller declares to share one convention, reads statistics over the group and returns configuration with the evidence behind it, which the caller applies; it never mutates a base `Parser` or a default and changes no parse. Proposed wording: "the parser never detects language; the group suggester may, says what it saw, and its answer is configuration the caller applies". The given-name table does not ask what language a name is; it asks whether a word is almost always a given name, anywhere. This entry is the first commit of the branch so the wording can be settled before the code is read; the only items recorded as decided are the two under TABLES (the private tables, the nam_dict approval); the rest of this file was proposed for review when this entry was written (decided since, 2026-11-15 ACCEPTED).

N (500) was chosen with the spikes (SIGNALS, top 100 against top 500); the family share and the use count were set once and not tuned, the THRESHOLDS measurement finding that the tables meet its constraint as built.
