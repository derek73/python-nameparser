## Log

- **2026-11-10 SCOPE — THE NEVER-DETECT-LANGUAGE RULE IS ABOUT THE PARSE, AND THE GROUP SUGGESTER IS OUTSIDE IT (PROPOSED, FOR REVIEW).** AGENTS.md's design philosophy says the parser never detects language, because the language of a Latin-script name cannot be read off the name. `Parser.suggest` works on a group the caller declares to share one convention, reads statistics over the group and returns configuration with the evidence behind it, which the caller applies; it never mutates a base `Parser` or a default and changes no parse. Proposed wording: "the parser never detects language; the group suggester may, says what it saw, and its answer is configuration the caller applies". The given-name table does not ask what language a name is; it asks whether a word is almost always a given name, anywhere. This entry is the first commit of the branch so the wording can be settled before the code is read; the only items recorded as decided are the two under TABLES (the private tables, the nam_dict approval); the rest of this file is proposed, for review.
- **2026-11-10 TABLES — TWO PRIVATE COMPILED TABLES, READ BY THE SUGGESTER ONLY (THE PRIVATE TABLES AND THE NAM_DICT DERIVATION DECIDED; THE REST PROPOSED, FOR REVIEW).** The romanized surnames (zh, ko, vi) and the common given names are written by tools under `tools/vocab/`, like `familiar.py`, into committed private modules under `nameparser/config/`, with a test that each is current. They are not `Lexicon` kinds for the first version, because a `family` reading on `Lee`, `Song` or `Long` would move the suffix gates derived from name readings and a `given` reading would move titles and particles; a table no parse reads moves no snapshot. Making them `Lexicon` kinds later, if a caller needs to tune them, stays open. The given-name table is derived from nam_dict's 55 country columns (top N per country by frequency band, unioned), keeping a name only if ORCID's researchers wrote it in the family box at most 5% of the times they wrote it (at least 20 uses), it is longer than one letter and it is not in the romanized surname sets. N (500) was chosen with the spikes (SIGNALS, top 100 against top 500); the family share and the use count were set once and not tuned, the THRESHOLDS measurement finding that the tables meet its constraint as built. Licences: nam_dict GNU FDL 1.2, ORCID's public data file CC0, Unihan the Unicode licence; the module header carries the sources once. The table derived from nam_dict is approved.
