# W4 — script-scoped order

## Standing

- The family-first override is keyed to the script of the written name, never a guessed language, and Latin transliteration is untouched: `김 민준` and `山田 太郎` read family-first under every declared order, while `Kim Min-jun` reads given 'Kim' by default — 2026-07-27.
- Han and kana together with at least one kana is licensed Japanese: `高橋 みなみ` → family '高橋' under every declared order — 2026-07-29 #272.
- A wholly-katakana name keeps the declared order because its script cannot tell a Japanese reading from a transcription, halfwidth included (`マイケル ジャクソン` → given 'マイケル', `ﾔﾏﾀﾞ ﾀﾛｳ` → given 'ﾔﾏﾀﾞ'), and a caller who knows adds `(Script.KATAKANA, FAMILY_FIRST)` to `script_orders` — 2026-10-03 #594.
- The halfwidth kana block U+FF65–FF9F is katakana in the script table, decided by widening the table and not by an NFKC fold, which reaches past the kana (`ＪＯＨＮ`, `㈱`): `山田 ﾀﾛｳ` → family '山田', and `ﾀﾅｶ. John` reads given 'ﾀﾅｶ.' and no title — 2026-10-03 #594.
- A voicing mark standing after a kana takes that kana's script, in the classification copy only: `ア゙イ タロウ` keeps the declared order (given 'ア゙イ'), `あ゙い たろう` → family 'あ゙い', `山田 ア゙イ` → family '山田'; a mark after anything else keeps the table's answer (`김゙민준` → given '김゙민준', undivided) — 2026-10-03 #596.
- Taking the voicing marks out of the hiragana range, and narrowing the fix to the two combining marks, are declined; a mark with nothing before it keeps the table's answer and reads family-first, unpromised (`゙アイ タロウ` → family '゙アイ' under every declared order) — 2026-10-03 #596.
- A name the 间隔号 divides keeps the declared order: `威廉·莎士比亚` → given '威廉' by default and family '威廉' under FAMILY_FIRST — 2026-10-03 #596; rules/W4 states the stand-down as an Except — 2026-10-20 (Derek), #761.

Elsewhere: the katakana middle dot divides like a space and its pieces read by the script license (`威廉・莎士比亚` → family '威廉'), decisions/T3's 2026-07-30 #298 entry on codepoint scope; a lone word in a script with no order of its own still reports `given-or-family` (`マイケル`), decisions/O5's 2026-09-07 #449 entry.

Open: none in this file.

- 2026-10-03 #594 (its voicing-mark argument against an NFKC fold superseded by #596 below) — HALFWIDTH KATAKANA IS KATAKANA. The script table classifies the halfwidth kana block U+FF65–FF9F as `Script.KATAKANA`, so `山田 ﾀﾛｳ` reads family 山田 as `山田 エミ` does; every release through 2.3.0 left the block unclassified and read it given 山田, family ﾀﾛｳ, the positional reading. Legacy data written for JIS X 0201 systems, which had no kanji, spells names this way — bank, payroll and CSV exports. DECIDED by widening the table rather than by folding: nothing rewrites the text before parsing (rules.md's T Background), so normalization at tokenize was never available, and an NFKC fold at classification — the other place the issue offered — reaches far past the kana (`ＪＯＨＮ` to `JOHN`, `㈱` to `(株)`), and it would move a wholly-katakana name across W4's line: a voicing mark with no precomposed form to join (`ｱﾞ`, `ﾝﾞ`) folds to the COMBINING U+3099, which sits in the HIRAGANA block, so the folded token reads as kana-licensed Japanese and `ｱﾞｲ ﾀﾛｳ` would read family-first where the unfolded one keeps the declared order (measured 2026-10-03 by parsing the NFKC spelling `ア゙イ タロウ`, which reads family `ア゙イ`; a two-input sweep of halfwidth names against their NFC(NFKC) spellings differed only where such a mark stood; RECOMPUTE: parse each halfwidth name and `unicodedata.normalize("NFC", unicodedata.normalize("NFKC", name))` and compare the fields). The interpunct flank guard is NOT the hazard, though an earlier wording of this bullet said it was: it reads raw text and asks only whether a character is classified at all, which hiragana and katakana both are. The same measurement shows a pre-existing gap the fold would have widened rather than created: full-width katakana typed with an uncomposable combining U+3099 already takes the kana license today. A block range is how the table already decides (U+30FB and the voicing marks are in by block), and it takes the voicing marks U+FF9E/U+FF9F in because they are spacing characters following their base. The span starts at U+FF65, the halfwidth nakaguro, which tokenize already treats as a separator (rules/T2), and stops short of U+FF61–FF64, whose U+FF61 is a full stop. Everything keyed on the table follows: the kana license, the second-East-Asian-word count that keeps a segmenter from being asked (`高橋一郎 ﾀﾛｳ`), the 间隔号's flank guard (`ﾀﾛｳ·ﾔﾏﾀﾞ` divides), and `_NO_INITIALS`, which closes the limit #cjk-full-stops recorded (`ﾀﾅｶ. John` read title `ﾀﾅｶ.`). THE RATIONALE FOR WHOLLY-KATAKANA NAMES IS AMENDED, NOT THE BEHAVIOR: a wholly-halfwidth name keeps the declared order exactly as a wholly-katakana one does (`ﾔﾏﾀﾞ ﾀﾛｳ` reads given ﾔﾏﾀﾞ), but the 2026-07-27 reason — that such names are predominantly transcriptions — is weaker here, since a system with no kanji wrote Japanese names in katakana too, family-first. What stands is the narrower claim: the script cannot tell a Japanese reading from a transcription, so it settles no order, and a caller who knows their katakana is Japanese adds `(Script.KATAKANA, FAMILY_FIRST)` to `script_orders` (docs/usage.rst's Boundaries section carries the recipe). `name_order=FAMILY_FIRST` works too, at the cost of reversing Latin names as well. - 2026-10-03 #596 — A VOICING MARK TAKES THE SCRIPT OF THE KANA BEFORE IT. The four kana voicing marks U+3099–309C are in the hiragana BLOCK, which is how the script table decides, but none belongs to either syllabary: a mark voices the kana it follows. NFC composes one only where a precomposed voiced kana exists (カ + U+3099 is ガ), so `ア゙イ`, `ン゙` and every spacing ゛/゜ kept a hiragana-block character inside a katakana word, the word took the kana license, and a wholly-katakana name read family-first — the gap the #594 entry above measured, present since 2.1.0. DECIDED by deleting, from the classification copy only, every mark standing after a KANA, so the word reads as its base's script; token text is untouched. A mark after anything else — hangul, Han, Latin, or nothing — voices no kana and keeps the table's answer, as before. That scope is a review finding, not a nicety: the first cut deleted every mark with ANY character before it, which handed `김゙민준` the hangul script, and the surname division, which cuts the raw text, then split the mark off its base — given 김, family `゙민준`, unreported, where 2.3.0 left the word whole and reported given-or-family; `parser_for(locales.ZH)` cut `王゙小明` the same way. A case row watches `김゙민준` — marked tolerated, the reading of a mark after a non-kana being unpromised (rules.md's W Background) — so the radar tier, not the contract, sees it move. Declined: taking the marks out of the hiragana range instead. Measured 2026-10-03 on patched copies of this tree, it fixes the katakana names as well but leaves a word holding a mark in NO script, so `あ゙い たろう` loses family-first, `山田 ア゙イ` loses the kana license and reads family `ア゙イ`, and the unspaced `山田ア゙イ` reads given; the two parity case rows #596 added pin those readings.
