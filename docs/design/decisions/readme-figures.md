# readme-figures — the measurements behind the README's rounded figures

README.rst is the PyPI project page. Its "How well it reads names" and "Speed and testing" sections quote figures that nothing in the repository re-runs, so each is a dated snapshot (root AGENTS.md, Counting claims), and this file is where the dates, counts and commands stand. The local corpora the accuracy figures are scored on are fetched into a cache and never committed (tools/differential/README.md, "Local corpora"), so a figure here is re-taken with the command its entry names, on that day's fetch.

## Standing

- README.rst gives its accuracy and speed figures rounded and undated, as a general idea of what to expect and of how much a setting can change it, with a sentence saying they differ for every dataset; each figure rounds the latest measurement in this file's Log, and one that measurement no longer rounds to is changed on the README in the PR that re-takes it — 2026-11-15.
- The accuracy figures published are agreement with the boxes a name was filed in, on three fielded populations (US patent inventors, UK company filings, Czech election candidates), and one per-country figure showing what a pack changes with its cost beside it; ORCID's overall figure and the CLDR, GND and Wikidata rates are not published as accuracy — 2026-11-05 #1106.
- The speed figure is the median of seven passes of one default `Parser` over the committed snapshot's names after a warm-up, and the test count is what `pytest --collect-only` collects — 2026-11-07 #1147.

Open: none in this file.

## Log

- 2026-11-05 #1106 — THE README PUBLISHES FIELD AGREEMENT ON THREE FIELDED POPULATIONS AND ONE PER-COUNTRY PACK FIGURE, AND NO OTHER RATE. Harvested 2026-11-15 from the README text PR #1106 added and from that PR's body, when the dated text left the README (the 2026-11-15 entry below); the measurements are that session's, re-taken rather than spot-checked at landing, and the fuller report behind them was never committed. The README said, from #1106 until 2026-11-15, v3.0.0 and v3.0.1 included: "Measured 2026-11-05 against the 3.0 development tree, by comparing each reading with the boxes the name was filed in. That is agreement with someone else's convention, not ground truth, after folding case, periods, commas and spacing." Its figures:
  - US patent inventors (`patentsview-inventors`, 657,991 distinct name-and-country records, split into two boxes by the filing attorney): both boxes agree for 94.7%, and for 98.0% outside Spanish- and Portuguese-speaking countries.
  - UK company filings (`psc-individuals`, people with significant control, 1,039,144 records scored, typed into title, forename, middle and surname boxes): all four agree for 96.8%.
  - Czech election candidates (`cz-candidates`, 170,181, with degrees before and after the name): all four boxes agree for 97.0%, and for 97.5% with `locales.CS`.
  - ORCID researchers (`orcid-researchers`) in Spain: `parser_for(locales.ES)` lifts agreement from 49.5% to 96.7% (Mexico 33.6% to 96.9%). The pack's cost where people file a single surname: Argentine patent inventors agree 93.8% by default, 86.2% under `ES` and 92.7% under `ES_AR`.

  Per the PR body: the Spain, Mexico and Argentina figures come from the per-country score, which reads each group's first 20,000 records (`uv run python tools/differential/config_diff.py score default plain:ES plain:ES_AR --group ES --group MX --group AR`); the others from `uv run python tools/differential/local_agreement.py <corpus> --record --out <scratch>` (and `--locale cs`). ORCID's overall figure is left out because most of its gap is the default's one-family-name convention on Spanish and Portuguese names, and the CLDR, GND and Wikidata rates because CLDR's names are fictional and the other two are sampled by shape rather than by frequency.
- 2026-11-07 #1147 — THE README'S SPEED AND TESTING FIGURES, EACH WITH ITS RECIPE. Harvested 2026-11-15 from the README text PR #1147 added and from that PR's body; the measurements are that session's, taken on master at 83e499d4 plus that PR's docs-only commits, Apple M3 Pro, one core, Python 3.11.17. As the README said until 2026-11-15:
  - "About 90 µs a name, some 11,000 names a second": one default `Parser()` parsing every non-empty `name` of `tools/differential/snapshot.jsonl` (7,106 entries, 6,897 distinct names, 209 entries repeating a name under another `name_order`, which the recipe ignores), one warm-up pass, then the median of seven passes timed with `time.perf_counter`. Three runs gave 89.4, 91.4 and 91.2 µs; the same script on 3.14.7 gave 83.1 µs. The snapshot holds CLDR's fictional renderings, so this is a timing workload and no accuracy claim.
  - Building a parser, in a fresh process after one `parse()`: the first `parser_for` of a language choice 37 to 51 ms (`PT` or `ES` first), mostly the one-time load of the reading index, which a reviewer measured at 27.5 ms; a different choice after it 6.8 to 7.4 ms; the same choice again about 1.2 ms; a default `Parser()` about 11 µs. The README gave these as "tens of milliseconds", "a few milliseconds" and "about 1 ms".
  - "Linear in the input, on the shapes the scaling tests repeat": 32 clock-timed shapes, `len(_SHAPES) + len(_PREFIXED_SHAPES) + len(_POLICY_SHAPES)` = 23 + 7 + 2 in `tests/v2/test_benchmark.py`, each timed with its repeated part `_FACTOR` (4) times as long and failing when the cost grows `_MAX_RATIO` (6.0) times or more.
  - "40,256 tests": `uv run pytest --collect-only -q -n0 | grep -c ::`, 39,652 of them under `tests/v2/`; 25 skip without the `ja` extra, which CI's `ja-extra` job runs with the rest of `tests/v2/`; the `build` jobs run the suite on each of Python 3.11 through 3.15, and `source-tree` runs it from a `git archive` export without nameparser installed.
  - The README also said that every corpus name's reading is recorded in the committed snapshot and a test fails when one moves (tools/differential/README.md; `tests/v2/test_snapshot.py`), and that the parsing rules are written down with examples the suite runs, a known gap carrying a `deviates:` marker (docs/design/rules/README.md). Both stand; the README no longer says them.
