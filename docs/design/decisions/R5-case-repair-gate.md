# R5 — the case-repair gate

## Standing

- Case repair acts only on a name written entirely in one case, and a name whose words outside the suffix are written in more than one case is kept as written, whether that casing is right not entering into it (`juan mcdonald` → 'Juan McDonald', `SHIRLEY MACLAINE` → 'Shirley MacLaine', `Shirley Maclaine` kept), unless repair was asked for anyway (`Shirley Maclaine` forced → 'Shirley MacLaine'); the refusal predates the git history and the override shipped in 0.4.0, and the suffix's place in the test is the next line's — 2026-08-29 (#407 arc); 2026-08-29, WHY R5'S STATEMENT WAS REWORDED; 2026-09-23 #492, DECIDED.
- The boundary example of rules/R5's main fence is the forced `Shirley Maclaine` line, the refusal being R5's effect rather than its absence, and no example witnesses an already-correct mixed-case name, kept and repaired being the same string there — 2026-08-29, why the gap survived; 2026-08-29, WHY R5'S STATEMENT WAS REWORDED.
- The rule names no route for the override: there are two, `capitalized(force=True)` per call and the v1 `force_mixed_case_capitalization` attribute the facade still honors (set on a private `Constants`, `HumanName('Shirley Maclaine')` and a bare `.capitalize()` give 'Shirley MacLaine') — 2026-08-29, the override has TWO routes.
- `capitalized_forced` is a test-side pseudo-field the doc runner resolves, not a parser field — 2026-08-29, `capitalized_forced` is a test-side pseudo-field.
- Forcing repair does not make the output independent of how the input was cased, so rules/R5 does not state that it does; the property is pinned in tests/test_capitalization.py, where `JUAN Y GARCIA` and `juan y garcia` both give 'Juan y Garcia' since a one-case name stopped reading a bare capital connective as an initial — 2026-08-29, WHAT THE OVERRIDE DOES AND DOES NOT PROMISE; 2026-08-29, and therefore NOT stated in rules; 2026-09-13 #383/#479.
- The gate reads every token but the suffix-roled ones, a suffix saying nothing about how the writer cased the name (`juan garcia III` → 'Juan Garcia III', `JUAN GARCIA Jr.` → 'Juan Garcia Jr.'), nickname and maiden included (`jane doe nee SMITH III` and `juan garcia (Bob)` kept as written); forcing was not the answer, being lossy on correctly cased names (`Danny DeVito` forced → 'Danny Devito') — 2026-09-23 #492, DECIDED.
- The parser's one-case readings still count a cased suffix where the gate does not, so one name can be mixed to the parser and one-case to repair: `john e jones III` → 'John e Jones III' against `john e jones iii` → 'John E Jones III', `jack MA` → 'Jack MA', and `MD, PhD` → 'Md PhD' — 2026-09-23 #492, THE R5 / PARSER SPLIT.
- A title stays evidence, title repair being plain `str.capitalize()` (`Dr. juan garcia` kept, `dr. juan garcia III` → 'Dr. Juan Garcia III'), which may move once title repair is trusted — 2026-09-23 #492, TITLES STAY EVIDENCE.
- Where repair is not forced the same one-case test is asked of each suffix on its own, so a suffix written in more than one case is kept as written (`john smith EdD` → 'John Smith EdD', `john smith B.Tech.` → 'John Smith B.Tech.'), at the accepted cost of keeping a garbled spelling with the deliberate one (`juan garcia Iii` → 'Juan Garcia Iii', 'Juan Garcia III' forced); force repairs both — 2026-09-24 #492.

Not standing: the debt the extraction left rules/R4, discharged there — 2026-08-29, DEBT this extraction leaves; the #492 measurement, which decides nothing — 2026-09-23 #492, MEASURED.

Elsewhere: the masks that serve a one-case name this rule cannot reach (`john smith psyd` → 'John Smith PsyD') — decisions/R4's 2026-09-24 #459 entry; the debt discharged — decisions/R4's 2026-08-29 DEBT DISCHARGED entry; the parse-time case fact still counting the judged suffix (`Jack MA`) — decisions/S6's 2026-09-23 #492 entry; a one-case single-letter connective read from vocabulary — decisions/P8; the v1 test of `juan garcia III` no longer an expected failure — decisions/v1-xfail-triage's 2026-09-23 #492 entry.
