# P5 — bound given names

## Standing

- The join is vocabulary-driven: a bound given-name word joins the name word after it, and needs a name word to spare — 2026-06-30.
- `abd` is a bound given-name word and the credential ABD, position deciding at the two ends (`Jane Smith ABD` → suffix, `Smith, Abd` → suffix 'Abd'); the three-token `abd al rahman` does not join, `al` chaining forward as a particle — 2026-08-18.
- The join never absorbs a lone maiden marker, and the reserve counts the name the marker pass leaves (`abdul Berg née Jones` → family 'Berg') — 2026-08-21 #411; 2026-08-21 #418.
- A given-name title licenses the join with one word to spare, read through the predicate H1 reads a title run with: `Sheik abdul salam` → given 'abdul salam', `Dr. abdul salam` → family 'salam'. The licensed join takes one word, never a particle chain (`Sir abdul van der Berg`), and a bound word that is also a particle reads as the bound word, reporting nothing (`Sheik Abu Bakar`) — 2026-08-22 #369.
- The join declines a word that reads as a suffix: `abdul Jr Smith Berg` → given 'abdul', `abdul Ph. D. Smith Berg` → suffix 'Ph. D.' — 2026-08-22 #401.
- S2's trailing run is read once before the join is tried, so the words to spare are the name pieces it leaves and the join moves no suffix reading (`abdul J. V` → given 'abdul J.', family 'V'; `Sheik abdul Ma` reports `suffix-or-name`) — 2026-10-07 #614.
- After a family comma the pair is the given name whatever follows (`Berg, abdul V` → given 'abdul V'), a bare ambiguous acronym the run does not take is a name word (`abdul Ma Smith` → given 'abdul Ma'), and a title word inside the name joins like a name word (`abdul Sir Smith Berg`) — 2026-08-22 #425.
- The join declines a title word a trailing rule reads as a title: after a family comma one H5's trailing run takes (`Berg, abdul Prof.` → title 'Prof.'), and past the second comma any title word — 2026-10-11 #637.

- 2026-08-18 — `abd` ADDED, and the reserve count corrected to let it work. It is the transliteration for the spellings that write the article as its own word ("Abd Allah", "Abd al-Rahman"), which abdul/abdel/abdal do not match; the Arabic-script عبد has covered the same word since #269, so only the Latin side was short. Not a C-ii collision, though it looks like one: C-ii settles a PRECEDENCE by frequency where neither reading is a name, and here one reading is a name and neither had to be given up. It is C-i's positional qualifier (2026-08-17) applied to a bound-given word — the naming use is LEADING, the credential use trailing, which is the `de` row of that table ('a TRAILING surname — no clash') rather than the `vd` row. `abd` is also the postnominal ABD ("All But Dissertation") in SUFFIX_ACRONYMS, and all three credential spellings still parse ("Jane Smith ABD", "Jane Smith, ABD", "Jane Smith A.B.D.").

- 2026-08-21 #411 (PR #416) — the reserve counts the name the join will actually leave behind, and the join never absorbs a marker. P5 has always said the join "needs a name word to spare, so two name words alone do not join"; the count was taken while the maiden marker and the maiden name were still pieces, because group's marker pass runs later in the same stage. `abdul Berg née Jones` counted four words, joined, and left no family name at all — given 'abdul Berg', family ''. That spelling is the pre-existing witness: it reads the same way at 2.0.0 and 2.1.0. `abd` does NOT — it reads correctly at 2.1.0 and acquired the defect only when #400 made it a bound given-name word this cycle, so for that spelling this is a regression #400 introduced and this closes. #399's chain stop widened the class again by putting the particle spellings in front of the reserve for the first time.

  Excluding the departing words is not sufficient on its own, and review is what established that. Where the maiden walk stops at an inner suffix the excluded span is short, enough words survive it to clear the threshold, and the join fires and takes the MARKER — after which nothing leaves and the count that authorised the join was reasoning about a name that never came to be. So the join now declines outright when the piece it would absorb is a marker, which is what P5 meant all along: it joins the bound word to a name word, and a marker is not one. Tested directly rather than through the span, because the two differ exactly where it matters — a marker with nothing but a suffix after it has no span at all, yet the join would still have absorbed it (`Berg, abdul née PhD` read given 'abdul née').

  What sharing `_maiden_span` between the count and the marker pass buys is one definition of what a maiden span IS. It does not make the two agree about what leaves: they run at different times on different piece lists, and the join between them could invalidate the span the count was taken against. Forbidding the join to absorb a marker is what closes that, not the sharing — the sharing only keeps the two from disagreeing about the span itself.

  Two consequences. It closes the P5 half of the join-swallow #412 records, so that issue narrows to P3's connective join (closed the same day by the #412 / #417 / #418 entry under M2, which also retires this entry's by-hand exclusion). And where the bound word is also suffix vocabulary, a declining join after a family comma leaves the S2 suffix reading and the name has no given name at all — `Berg, abd née Jones` reads family 'Berg', suffix 'abd', maiden 'Jones', which is exactly how `Berg, abd` alone has always parsed. `abd` is the only shipped word in both sets.

  Two alternatives to the exclusion, recorded so "reorder" is not read as one option with one price. The rejected one moves the maiden handler ahead of the PARTICLE CHAIN, which changes what the consumer receives for every name — that is the scope objection, and it stands. A narrower one was not weighed at the time: move the marker pass to run after P2/P3's joins but BEFORE P5, inside _group_segment rather than in group(). Under that arrangement the reserve counts the surviving name directly, so the span prediction, the exclusion and the marker guard all disappear, and P2/P3 are untouched. Its real cost is ordering against the tail-segment delimiter-core drop, which today runs between the joins and the marker pass and would be reversed for comma tails — unmeasured, which is why this records the option rather than taking it.
