# vocabulary-model — each word described by its readings (2026-10-15 → 2026-10-18)

The vocabulary was a set of base sets plus marker subsets (`particles` and `particles_ambiguous`, `suffix_acronyms` and `suffix_acronyms_ambiguous`, `suffix_words` and `honorific_tails`, `titles` and `given_name_titles`, `conjunctions` and `conjunctions_ambiguous`), and the pairs did not work as a model. "Ambiguous" meant three different things by field (may be a given name, may be a surname, may be an initial), and two of the markers were not ambiguities at all. The direction flipped between layers: config/ marked the never-given particles while `Lexicon` marks the may-be-given ones. Every marked entry was written twice and the checks on the pairs were uneven (a `Lexicon` raise for some, an import-time assert for others, nothing for `conjunctions_ambiguous`). A clash between categories (`do` as a particle and as a credential) was recorded nowhere, visible only because two sets happened to overlap, and nothing told an author whether an overlap they created was intended (`titles ∩ particles`, the title/suffix duals) or forbidden (acronyms ∩ words). Language packs need to say which language a word belongs to, and sets cannot.

## Standing

- The vocabulary redesign comes before adding many packs: it is designed for 3.0, and what is safe is pulled forward in four phases, (1) the data format and a compiler, snapshot-neutral, (2) derived ambiguity with the gate on every reading kind, (3) pack semantics, (4) the rules menu, order and shapes, and the output model — 2026-10-15/16.
- Each word is described by its readings (word → reading → properties), each kind belonging to one category that decides the compiled field it feeds; detailed kinds are recorded even where the kinds of a category behave alike, generation and credential being separate kinds among the suffix category's six (`generation`, `credential`, `honorific`, `professional_honorific`, `status`, `courtesy`) — 2026-10-15/16; 2026-10-18 #737.
- A language file holds the words the parser might meet in names written in that language, immigrant particles included, not the words of its etymology, and a word sits in the file of every language whose names it occurs in, a Latin transliteration in its source language's file; `mul.toml` holds the words shared on purpose instead (the generations `i` to `v` and `2`, `&`, and the European titles below) — 2026-10-15/16; 2026-10-18 #737; 2026-10-19 #749; 2026-10-19 #750, title kinds.
- The default loads every language and keeps working for names of any language. Choosing a language is to narrow it in phase 3 (#753): a pack is to settle only the clashes where its language has a vocabulary reading, a strict pack to drop other languages' name-level readings too, and a pack's preferred reading to be able to outrank one a shape rule derives — 2026-10-15/16.
- `e`, `y` and `i` stay in the default; choosing a language is to settle their one-case fork, which no shipped pack does yet — 2026-10-15/16.
- A patronymic field is to come in 3.0, and the particle kinds already draw the `clan`/`patronymic` line for it: a patronymic is followed by a parent's name, a clan prefix by a family name the lineage shares — 2026-10-15/16; 2026-10-19 #749.
- Gender is recorded only where a word gives a definitive clue: a feminine form or one half of a fixed pair, never an unmarked noun — 2026-10-15/16; 2026-10-19 #750, title kinds.
- Title-phrase modifiers are to count as titles only next to a head title; the rule is parked, and until it is designed the `modifier` kind is read as every title is (`Vice John Smith` → title 'Vice', while `John Smith Vice` keeps family 'Vice') — 2026-10-15/16; 2026-10-19 #750, title kinds.
- Name readings are hand-declared, and only on a word some language file claims as vocabulary or refuses, so the vocabulary carries no surname list (the segmentation lists, Korean and the ZH pack's, are outside the per-word model) — 2026-10-15/16; 2026-10-19.
- Bearer counts are structured provenance (source and count), never used to compute a reading — 2026-10-15/16.
- `Dean Smith` reads given `Dean`. The contested-head gate is to cover only words outside `titles` (`dean`, `justice`, `major`), and a title that is also a given name is decided one word at a time — 2026-10-15/16.
- Order and shape are separate: a language supplies only a default order, and the shapes (where titles, suffixes, particles and commas sit) belong to each order and live in the core; vocabulary readings are to settle a clash and name readings only to keep the gate on — 2026-10-15/16.
- `cased` replaces `capitalization_exceptions` and, with `same_as`, a canonical spelling, and a reading's `native` spelling is for surfacing; `acronym` is a reading property replacing the acronym/word split, one suffix kind per word; `expands` records the meaning an entry was added for; `addresses` takes `family` and `given`, `full` and `any` being refused until a later phase — 2026-10-15/16; 2026-10-18 #737.
- The vocabulary is per-word TOML in `nameparser/vocab/<tag>.toml`, one file per BCP 47 tag plus `und` and `mul`, at `schema = 1` (a compiler refuses a newer one), every reading a table and no `language` key; `tools/vocab/build.py` compiles it into a committed `nameparser/config/_compiled.py`, the parser never reads the TOML, and parsing it at import was declined — 2026-10-18 #737.
- The marker sets are explicit flags on readings (`may_be_given`, `may_be_name`, `may_be_initial`, `attached`, `addresses`, `cased`), not yet derived from name readings; `may_be_given` is stated on every particle, never defaulted, and two kinds of one word must agree on it — 2026-10-18 #737; 2026-10-19 #749.
- Exclusions are data: an `excluded` key refuses a kind, a category or a behavioral property, in the file of the language whose reading it refuses, and the build refuses the excluded thing in any file, quoting the reason — 2026-10-18 #737.
- A per-word fact that moves into the TOML is replaced in decisions/ by a query that finds it (decisions/README.md, edit kind 4) — 2026-10-18 #737.
- The script is read from the word, not the file: a script subtag is only for a difference the text cannot show — 2026-10-18 #737.
- The names later phases will use (`default`, `prefer`, `strict`, the position and attachment keys) are build errors naming their phase, not inert data; locale-pack vocabulary and the Korean surname list stay in Python — 2026-10-18 #737.
- Every language file is in build-checked order (kind, then the `same_as` path from its root head, then the codepoints of the text), the check naming the entry to move, running last, and refusing a `same_as` loop of any length; `und.toml` is exempt — 2026-10-19 #747; 2026-10-21 #762.
- The particles take eight kinds beside the generic one, `expands` carrying a particle's gloss and `note` its vetting, and the particle keep-outs are exclusions — 2026-10-19 #749.
- The titles take ten kinds beside the generic one, `academic` and `occupation` divided by function rather than subject, and the title keep-outs are exclusions — 2026-10-19 #750, title kinds; 2026-10-19 #750, the rest of the titles.
- `wm` is no title: William's abbreviation reads as the given name it is (`Wm Smith` → given 'Wm'), and its title reading is refused in en.toml. The dotted `Wm.` opening the given part is still rules/H2's title; a given reading that outranks H2 belongs to phase 2 (#752) — 2026-10-22 #789.
- Abbreviations and full words spelled alike across European languages (`dr`, `prof`, `doctor`, `professor`, `docent`) are in `mul.toml`; a credential goes to a file only on evidence that names in that language carry it, so none is in `mul.toml` — 2026-10-19 #750, the rest of the titles; 2026-10-20 #751, the credentials.
- `und.toml` holds only `bon` and `dí`, particles of unrecorded origin; every other word, the credentials, conjunctions, bound given names and birth markers included, is in a language file or in `mul.toml` — 2026-10-19 #749; 2026-10-20 #751, the conjunctions.

Not standing: the plans the classifications carried out, phase 1's mechanical conversion of the unclassified categories into `und.toml` (2026-10-18 #737) and the shared readings left in place until their categories were classified (2026-10-19 #749), both done by 2026-10-20 #751, the conjunctions; and #747's reason for exempting `und.toml`, its entries keeping the Python lists' order for its vetting comments to point along (2026-10-19 #747), overtaken once it held two entries and no such comment.

- **2026-10-18 #737 — phase 1 shipped: per-word TOML compiled to today's sets (approved by Derek, 2026-10-18, all eight of the spec's recommendations).** No parse, render or public name moves; it is a re-encoding plus the build checks the encoding makes possible.
  - **The format.** `nameparser/vocab/<tag>.toml`, one file per BCP 47 tag in canonical case (`pt-BR`, `zh-Hant`), plus `und` for words not yet assigned a language and `mul` for words shared on purpose (the Roman numerals). `schema = 1` is the only other top-level key: a new kind or property is additive and does not bump it, a change in what a key means does, and a compiler refuses a newer schema. Each `[[word]]` has a `text`, already in `_normalize` form, and zero or more readings keyed by KIND, each a TABLE (`generation = {}`, never `= true`) so a property can be added to any reading later. The file name is the language; there is no `language` key to drift from it.
  - **Kinds as keys, with generic category keys.** Each kind belongs to one category, and the category decides which compiled field a reading feeds. A category key is itself a kind (`title = {}`, a title not yet classified), so classifying a word later is a data edit that moves no compiled set. Kind names are unique across categories. Phase 1 classifies the SUFFIX category fully — `generation`, `credential`, `honorific`, `professional_honorific`, `status`, `courtesy` — and converts every other category mechanically into `und.toml` with its generic kind and today's flags, so the TOML is the single source from the first PR. One suffix kind per word replaces the import-time assert that the acronym and word sets are disjoint.
  - **Flags now, derivation in phase 2.** The marker sets became explicit properties — `may_be_given` on particles, `may_be_name` on acronym credentials, `may_be_initial` on conjunctions, `attached = { side = "after" }` for the glued peel, `addresses = "given"`, `cased` — rather than being derived from declared name readings, which would have meant declaring a given reading for `te`, `tho` and `du` that no count supports. Measured for the later swap: deriving both ambiguity markers from name readings reproduces them exactly if the readings are declared on exactly the flagged words, because no word sits in one marker set while needing to be absent from the other (`do` is in both; `mc` and `vd`, particles and credentials, in neither, consistent with #454). Recompute: `L = Lexicon.default(); L.particles_ambiguous & (L.suffix_acronyms - L.suffix_acronyms_ambiguous)` and `L.suffix_acronyms_ambiguous & (L.particles - L.particles_ambiguous)`, both empty.
  - **`may_be_given` is stated on every particle, never defaulted.** Found while converting, not in the spec: the old encoding stored the NEVER-GIVEN particles and derived the rest, so a new particle was ambiguous unless argued never-given — #293's safe-by-default and decisions/vocabulary-collisions C-i's "under uncertainty, ambiguous". A flag with a default would have picked one side of that silently (a bare `particle = {}` reading as never-given is the unsafe side), so the build refuses a particle reading without it.
  - **Exclusions are data.** `excluded` refuses a kind or category at word level, or a behavioral property at reading level (`honorific = { excluded = { attached = "…" } }`), with a reason. It lives in the file of the language whose reading it refuses, and the build refuses the excluded thing in ANY file, quoting the reason, so a contributor adding a refused reading meets the record of why. An excluded kind refuses itself whatever its properties, and every other kind compiling to the same set, so a generic `suffix = {}` cannot put back a refused `generation` (found in the PR review); the name kinds, which compile to nothing, refuse only themselves. A refused property is refused any value other than the one it takes unwritten on a reading of the excluding kind (false for the `may_be_*` flags, true for a credential's `acronym`, so a particle can still state `may_be_given = false` beside an exclusion of it), on any reading of its category — and `cased`, compiled once per word, on every reading of the word. The pilot carried the generational-words refusals, rai/cha/mai and the glued-peel refusals; the README states the exception that lets those sentences here become queries.
  - **Script is read from the word, not the file**, reversing the notes' premise that Serbian Latin and Cyrillic need separate files: `sr.toml` holds `mlađi` and `млађи` side by side. A script subtag is for what the text cannot tell apart, which in practice is Simplified and Traditional Han.

The TOML ships as package data for tools and later phases, and the parser never reads it.
