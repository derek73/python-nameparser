# vocabulary-model — each word described by its readings (2026-10-15 → 2026-10-18)

The vocabulary was a set of base sets plus marker subsets (`particles` and `particles_ambiguous`, `suffix_acronyms` and `suffix_acronyms_ambiguous`, `suffix_words` and `honorific_tails`, `titles` and `given_name_titles`, `conjunctions` and `conjunctions_ambiguous`), and the pairs did not work as a model. "Ambiguous" meant three different things by field (may be a given name, may be a surname, may be an initial), and two of the markers were not ambiguities at all. The direction flipped between layers: config/ marked the never-given particles while `Lexicon` marks the may-be-given ones. Every marked entry was written twice and the checks on the pairs were uneven (a `Lexicon` raise for some, an import-time assert for others, nothing for `conjunctions_ambiguous`). A clash between categories (`do` as a particle and as a credential) was recorded nowhere, visible only because two sets happened to overlap, and nothing told an author whether an overlap they created was intended (`titles ∩ particles`, the title/suffix duals) or forbidden (acronyms ∩ words). Language packs need to say which language a word belongs to, and sets cannot.

## Standing

  - **The format.** `nameparser/vocab/<tag>.toml`, one file per BCP 47 tag in canonical case (`pt-BR`, `zh-Hant`), plus `und` for words not yet assigned a language and `mul` for words shared on purpose (the Roman numerals). `schema = 1` is the only other top-level key: a new kind or property is additive and does not bump it, a change in what a key means does, and a compiler refuses a newer schema. Each `[[word]]` has a `text`, already in `_normalize` form, and zero or more readings keyed by KIND, each a TABLE (`generation = {}`, never `= true`) so a property can be added to any reading later. The file name is the language; there is no `language` key to drift from it.
  - **Kinds as keys, with generic category keys.** Each kind belongs to one category, and the category decides which compiled field a reading feeds. A category key is itself a kind (`title = {}`, a title not yet classified), so classifying a word later is a data edit that moves no compiled set. Kind names are unique across categories. Phase 1 classifies the SUFFIX category fully — `generation`, `credential`, `honorific`, `professional_honorific`, `status`, `courtesy` — and converts every other category mechanically into `und.toml` with its generic kind and today's flags, so the TOML is the single source from the first PR.
