# vocabulary-model — each word described by its readings (2026-10-15 → 2026-10-18)

The vocabulary was a set of base sets plus marker subsets (`particles` and `particles_ambiguous`, `suffix_acronyms` and `suffix_acronyms_ambiguous`, `suffix_words` and `honorific_tails`, `titles` and `given_name_titles`, `conjunctions` and `conjunctions_ambiguous`), and the pairs did not work as a model. "Ambiguous" meant three different things by field (may be a given name, may be a surname, may be an initial), and two of the markers were not ambiguities at all. The direction flipped between layers: config/ marked the never-given particles while `Lexicon` marks the may-be-given ones. Every marked entry was written twice and the checks on the pairs were uneven (a `Lexicon` raise for some, an import-time assert for others, nothing for `conjunctions_ambiguous`). A clash between categories (`do` as a particle and as a credential) was recorded nowhere, visible only because two sets happened to overlap, and nothing told an author whether an overlap they created was intended (`titles ∩ particles`, the title/suffix duals) or forbidden (acronyms ∩ words). Language packs need to say which language a word belongs to, and sets cannot.

- **2026-10-15/16 — the model (Derek).** Decided over a brainstorm whose notes are gitignored; the durable decisions are these.
  1. The vocabulary redesign comes before adding many packs; it is designed for 3.0 and whatever is safe is pulled forward.
  2. Each word is described by its READINGS (word → reading → properties), replacing the base-plus-marker pairs.
  3. Detailed kinds are recorded during the migration even where every kind of a category behaves alike at first; generation and credential are separate kinds (#326).
  4. A language file means "the words the parser might encounter in names in that language" — what occurs in names and records written in it, including particles common there through immigration — not words of that language's etymology.
  5. The default loads every language and keeps working for names of any language, as today; choosing a language narrows it.
  6. Packs prefer and strict packs restrict: a pack settles only the clashes where its language has a VOCABULARY reading, and a strict variant also drops other languages' name-level readings.
  7. `e`/`y`/`i` stay in the default, at least to start; choosing a language settles the one-case fork.
  8. A patronymic field belongs in 3.0.
  9. Gender is recorded only where a word gives a definitive clue.
  10. Title-phrase modifiers count as titles only next to a head title (parked, not filed).
  11. Name readings are hand-declared, and only for words some language file claims as vocabulary, so nobody maintains surname lists. (Widened 2026-10-19, below: or refuses.)
  12. Bearer counts are structured provenance (source + count), never used to compute a reading: two data sets deciding one reading would make the decision unclear. A new census flags changed names for review.
  13. `Dean Smith` reads given `Dean`, as today.
  14. Order and shape are separate: a language supplies only a default order; the shapes (where titles, suffixes, particles and commas sit) belong to each order and live in the core.
  15. Vocabulary readings settle a clash; name readings only keep the gate on.
  16. The contested-head rule covers only words outside `titles` today (`dean`, `justice`, `major`); a title that is also a given name today is decided one word at a time, like the graf class (decisions/salutation-titles).
  17. `cased` and `same_as` replace a "canonical" spelling, and `cased` replaces `capitalization_exceptions`; both default to the word, and a reading's `native` spelling is for surfacing.
  18. `acronym` is a reading property, replacing the `suffix_acronyms`/`suffix_words` split; `expands` records the meaning an entry was added for, not every meaning.
  19. `addresses_given` generalizes to `addresses = family | given | full | any`.
  20. A pack's preferred reading can outrank a reading derived by a SHAPE rule (period abbreviation, initials, capitals), not only a vocabulary reading.

  Phasing, fixed then: (1) the data format and a compiler to today's sets, snapshot-neutral; (2) derived ambiguity, with the gate extended to every reading kind — the step that changes behavior, with its own design; (3) pack semantics, needing 1 and 2; (4) the rules menu, order and shapes, and the output model.

- **2026-10-18 #737 — phase 1 shipped: per-word TOML compiled to today's sets (approved by Derek, 2026-10-18, all eight of the spec's recommendations).** No parse, render or public name moves; it is a re-encoding plus the build checks the encoding makes possible.
  - **The format.** `nameparser/vocab/<tag>.toml`, one file per BCP 47 tag in canonical case (`pt-BR`, `zh-Hant`), plus `und` for words not yet assigned a language and `mul` for words shared on purpose (the Roman numerals). `schema = 1` is the only other top-level key: a new kind or property is additive and does not bump it, a change in what a key means does, and a compiler refuses a newer schema. Each `[[word]]` has a `text`, already in `_normalize` form, and zero or more readings keyed by KIND, each a TABLE (`generation = {}`, never `= true`) so a property can be added to any reading later. The file name is the language; there is no `language` key to drift from it.
  - **Kinds as keys, with generic category keys.** Each kind belongs to one category, and the category decides which compiled field a reading feeds. A category key is itself a kind (`title = {}`, a title not yet classified), so classifying a word later is a data edit that moves no compiled set. Kind names are unique across categories. Phase 1 classifies the SUFFIX category fully — `generation`, `credential`, `honorific`, `professional_honorific`, `status`, `courtesy` — and converts every other category mechanically into `und.toml` with its generic kind and today's flags, so the TOML is the single source from the first PR. One suffix kind per word replaces the import-time assert that the acronym and word sets are disjoint.
  - **Flags now, derivation in phase 2.** The marker sets became explicit properties — `may_be_given` on particles, `may_be_name` on acronym credentials, `may_be_initial` on conjunctions, `attached = { side = "after" }` for the glued peel, `addresses = "given"`, `cased` — rather than being derived from declared name readings, which would have meant declaring a given reading for `te`, `tho` and `du` that no count supports. Measured for the later swap: deriving both ambiguity markers from name readings reproduces them exactly if the readings are declared on exactly the flagged words, because no word sits in one marker set while needing to be absent from the other (`do` is in both; `mc` and `vd`, particles and credentials, in neither, consistent with #454). Recompute: `L = Lexicon.default(); L.particles_ambiguous & (L.suffix_acronyms - L.suffix_acronyms_ambiguous)` and `L.suffix_acronyms_ambiguous & (L.particles - L.particles_ambiguous)`, both empty.
  - **`may_be_given` is stated on every particle, never defaulted.** Found while converting, not in the spec: the old encoding stored the NEVER-GIVEN particles and derived the rest, so a new particle was ambiguous unless argued never-given — #293's safe-by-default and decisions/vocabulary-collisions C-i's "under uncertainty, ambiguous". A flag with a default would have picked one side of that silently (a bare `particle = {}` reading as never-given is the unsafe side), so the build refuses a particle reading without it.
  - **Exclusions are data.** `excluded` refuses a kind or category at word level, or a behavioral property at reading level (`honorific = { excluded = { attached = "…" } }`), with a reason. It lives in the file of the language whose reading it refuses, and the build refuses the excluded thing in ANY file, quoting the reason, so a contributor adding a refused reading meets the record of why. An excluded kind refuses itself whatever its properties, and every other kind compiling to the same set, so a generic `suffix = {}` cannot put back a refused `generation` (found in the PR review); the name kinds, which compile to nothing, refuse only themselves. A refused property is refused any value other than the one it takes unwritten on a reading of the excluding kind (false for the `may_be_*` flags, true for a credential's `acronym`, so a particle can still state `may_be_given = false` beside an exclusion of it), on any reading of its category — and `cased`, compiled once per word, on every reading of the word. The pilot carried the generational-words refusals, rai/cha/mai and the glued-peel refusals; the README states the exception that lets those sentences here become queries.
  - **Script is read from the word, not the file**, reversing the notes' premise that Serbian Latin and Cyrillic need separate files: `sr.toml` holds `mlađi` and `млађи` side by side. A script subtag is for what the text cannot tell apart, which in practice is Simplified and Traditional Han.
  - **A build step, not a parse at import.** tools/vocab/build.py compiles the files into a committed nameparser/config/_compiled.py, one sorted entry per line, and the public constants stay where they were as `NAME = _compiled.NAME` assignments with their docstrings (autodoc's attribute scan needs an assignment) and the deprecated-alias bridge. tests/v2/test_vocab.py holds the committed module to a fresh compile and runs the checks with warnings as errors, the snapshot.jsonl pattern (mechanisms.md#COMPILED-DATA-COMMITTED). The TOML ships as package data for tools and later phases, and the parser never reads it.
  - **The comments moved with their words.** The suffix words' per-word facts became fields (`note`, `issue`, `same_as`, `expands`, `excluded`); the class-level parts of the vetting notes were checked against the decisions entries that already hold them, and what had no home went to decisions/W2's entry of this date. In the mechanically converted categories the block comments stand as TOML comments above the entry they stood above, in source order, and inline comments became reading `note`s; classifying those categories is the later work that turns them into fields.
  - **Measurement (2026-10-18, Python 3.11.17).** `Lexicon.default()` and all thirteen raw constants equal the pre-change tree's, compared against values pickled from master at 6803a261; `tools/differential/snapshot.py` reports "matches the snapshot". Negative control: dropping `may_be_name` from `ma` moves 120 snapshot entries and makes `Lexicon.default()` unequal, and editing the TOML without rebuilding fails the staleness test with the refresh command. `import nameparser` measured 48.5–48.8 ms median against master's 49.4 ms (25 fresh processes each, two runs), so the generated module costs nothing visible; the spike measured parsing the TOML at import at about +18 ms on a 48 ms import, and the TOML grows with descriptive data the compiled module never carries.
  - **Declined, with evidence.** PARSING THE TOML AT IMPORT: +18 ms net on every import (spike, 2026-10-18), and it could not be made lazy on 2.x without making the config modules and the shim's `CONSTANTS` lazy too. DERIVING THE MARKERS NOW: see the flags bullet. A `peelable` BOOLEAN: `attached` is the general property from the start, a table so its other side and separators can be added. A `language` KEY in the file: a second source of truth for the file name.
  - **Phases 2–4 are rejected by the compiler, not accepted as inert data**: `addresses = "full"`/`"any"`, `attached` on a side other than after, and the names later phases will use (`default`, `prefer`, `strict`, `bare_only`, `leading_only`, `trailing_only`, `attaches`, `separators`) are build errors naming their phase, so nothing reads as working that does not. Locale-pack vocabulary and the Korean surname list stay in Python: surnames are a segmentation list, outside the per-word model, and packs move in phase 3.
  - **Recompute the composition** rather than quoting it: `uv run python tools/vocab/query.py --kind generation --count` (readings, one per file a word is in), `--kind suffix`, `--excluded generation`, `--issue 661`.

- **2026-10-19 #747 — a build-checked word order (check 10).** No compiled set moves: the 41 language files that were out of order on cc030b9c were sorted (an entry moving with any comment above it), `tools/vocab/build.py --check` reports the committed module current, and `tools/differential/snapshot.py` matches. The order, stated in nameparser/vocab/README.md's Word order section, is kind in `CATEGORY`'s order, then the word's `same_as` path from its root head, then text, so the spellings of one word sit together under it before #750 moves the titles out of `und.toml`.
  - **Checked, not rewritten.** `tomllib` only reads, and a comment above an entry belongs to it, which no TOML reader can see; a rewriter would have to round-trip the files' comments. No checked file holds one on 2026-10-19 (every per-entry comment is in `und.toml`), but a word leaving `und.toml` before its category is classified carries its vetting comment with it. So the build refuses a file out of order, naming the entry to move (the first outside a longest run already in order, so a word appended at the end is named rather than its neighbours) and its place against that run, so following the messages takes the fewest moves (#767's second review found the place first given beside a neighbour itself out of place, which took up to 22 moves where 10 would do).
  - **Run last.** Check 10 runs after every other check, so a contributor adding a refused word to a language file meets the exclusion's reason (check 6) rather than an order error, the precedence check 6 is placed first for; the first version ran it at the end of loading, ahead of check 6, and the review of #767 found an excluded word appended to en.toml reported as out of order.
  - **The same_as path, not the direct target, and the file's own path.** Keyed by the direct target, a spelling of a spelling sorts apart from the word it spells: ar.toml's `ed-` (same_as `el-`, itself same_as `al-`) would follow `ul-`. The path keeps each spelling under its own head inside the root's group, and it follows only the file's own entries, so a word that is a head in one file and a spelling in another does not make one file's order depend on the other (#767's review found the first version, which followed a map taking each word's first file, accepting `jnr` before `jr` in en.toml once de.toml made `jr` a spelling).
  - **No same_as loop, over every same_as written.** Check 7 refuses only a same_as naming its own word. Check 10 refuses any longer loop, in every file, `und.toml` included, over every same_as of every reading: no check holds a word to one head across files or kinds, and the first version, which walked one head per word, passed a loop running through a second file's or a second kind's same_as.
  - **Codepoint order of the normalized text.** Defined for every script and every machine, and no one language's collation; the cost is that within a script a precomposed accented letter follows `z` (`aḍ-` after `az-`), and that a traditional and a simplified spelling with no `same_as` between them sort apart (`課長`, `课长`).
  - **A refusal sorts under the kind it refuses.** Forty-six language-file entries on 20b595b2 (`senior`, `fils`, the Slavic `ml` and `st`) hold no vocabulary reading, only an exclusion and sometimes the name reading that is its evidence; they sort beside the words they were refused as.   - **`und.toml` is exempt.** Its entries keep the Python lists' order, which its vetting comments still point along (a neighbour "above" or "below"); each category's classification moves its words out, into files that are checked.
