The Japanese install hint is conditional — it appears only when a Japanese script is among the dead scripts; a hangul-only gap gets the generic remedies.
- 2026-08 #337 — the warning exists because parser_for(locales.JA) without segmenter= used to build a parser that silently behaved like a working one minus the feature; it re-emits from the parser_for frame so the reported location is the caller's own call.
- 2026-08-07 #339 — diagnostics that hand the reader code must hand code that type-checks: the message's offered deactivation used a bare tuple literal for segment_scripts — an arg-type error under mypy in a py.typed package — and became frozenset(), pinned by a test asserting the offered spelling. The known-bad spelling is in the denylist test. The structural fact behind the recurrence: autodoc renders docstrings into the API reference, so docs/*.rst is NOT the boundary of "the docs" — a guide and the reference can teach different spellings on the same rendered page, invisibly to any .rst-only sweep.
- 2026-10-31 #984 — THE COMMAND LINE ATTACHES THE INSTALLED JAPANESE SEGMENTER; `parser_for` STAYS EXPLICIT. `python -m nameparser --locale ja` tests for namedivider with `importlib.util.find_spec`, and where it is present passes `locales.ja_segmenter()` to `parser_for`, any failure to load it (an `ImportError` from numpy, an `OSError`) propagating with its own message; only the package's absence falls back, a broad `except ImportError` having reported a broken install as a missing one. Where it is absent the CLI prints a note naming `pip install 'nameparser[ja]'` and filters this warning by its message: its other remedies (covering surnames, `segmenter=`, `Policy(segment_scripts=frozenset())`) are code a command line cannot pass, and a print shows where `PYTHONWARNINGS=ignore` would hide a warning. The CLI is a debug tool with no other way to attach one, so its reading may depend on the environment it runs in. **Declined:** doing the same in `parser_for(locales.JA)`. The same code would parse `高橋一郎` differently with and without the extra installed; a `Parser` holding `ja_segmenter()` cannot be pickled, its segmenter being a local closure, so `parser_for(locales.JA)` would stop pickling wherever the extra is installed; and the pack-and-segmenter pairing is explicit by design (`locales/ja.py`'s docstring). The inert registration this file's first entry pins stays the library's behavior.
