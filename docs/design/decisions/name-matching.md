# name-matching — grouping keys and a consistency check that explains itself

## Standing

- Name matching answers "could these two names be the same person?" with a verdict and a per-role table, never a score: `MatchResult.consistent`, and one `RoleMatch` per `Role` in `Role` order holding the outcome, both sides' text and the side that carried more; consistent means nothing in the two names contradicts the match under the accepted outcomes, not that they name one person — 2026-11-08 #1006.
- One settings object, `Matching`, made from a `Parser` (`Parser.matching(accept=...)`), holds the accepted outcomes, and both `check` and `keys` are its methods, so keys built under one setting are never checked under another; `accept` replaces the default rather than extending it, `same` is always in it and `conflict` never can be — 2026-11-08 #1006.
- The default accepts the writing variants (`same`, `folded`, `listed-spelling`, `particles-aside`, `part-of-other`, `initial`, `initials-agree`, `one-side`, `generation-one-side`, `noted`); `family-initial`, `given-one-side`, `hyphenated-part`, `other-reading` and `across-roles` are opt-in, reported in the table either way — 2026-11-08 #1006.
- The family role must be filled on both sides and agree, under every setting: a name with no family name is consistent with nothing and has no key — 2026-11-08 #1006.
- The check is symmetric (`check(b, a)` is `check(a, b).mirrored()`) and not transitive; a direction is read off `RoleMatch.more`, never a second call — 2026-11-08 #1006.
- Keys follow the accepted outcomes, with the guarantee that two names the check calls consistent share a key: one `word;g` key per folded family-base word (and each half of a hyphenated one beside its joined form), `g` the given name's first letter, each word under both headword orders — 2026-11-08 #1006.
- The fold drops case, full stops, apostrophes and a combining mark on a Latin, Greek or Cyrillic letter, and keeps a mark on any other script's letter — 2026-11-08 #1006.
- `part-of-other` compares the two family bases, particles excluded, so a family of particles alone is part of nothing — 2026-11-08 #1006.
- `other-reading` is searched only where it is accepted and the names as parsed are not consistent, one ambiguity per side at a time, never into the title or suffix — 2026-11-08 #1006.
- `across-roles` is searched only where it is accepted, counts only a full name on both sides (`same`, `folded`, `listed-spelling`), and consumes the middle word it uses — 2026-11-08 #1006.

Elsewhere: `matches()` and `comparison_key()` stay exact, one casefolded component per field (decisions/comparison-surface, whose Declined line on lenient matching this file's entry supersedes in part).

## Log

- **2026-11-08 #1006 — NAME MATCHING IS A VERDICT AND A PER-ROLE TABLE, NEVER A SCORE, WITH GROUPING KEYS THAT FOLLOW THE ACCEPTED OUTCOMES.** Callers who parse many names from several sources to find the same person (OpenAlex's author bylines, NASA ADS's author search, the Palace Project against VIAF, uwcourses' instructors; their code surveyed 2026-11-08) all parse, flatten the result back to a string and compare strings, throwing away the structure the parse found exactly where it is needed. `Parser.matching()` keeps it: `keys()` to group, `check()` to compare a pair role by role. The design was settled with the maintainer in a design session on this date; the calls marked as implementation calls below were made while building it, not by the maintainer. Measured: nothing over a corpus yet; the behavior rests on `tests/v2/test_match.py`, whose symmetry and key-guarantee properties run over one shared parsed grid. SUPERSEDES IN PART: decisions/comparison-surface's Declined line on lenient matching, for initials-compatible matching, which ships here beside `matches()`; a nickname table stays declined.
  - Decided: a verdict plus a per-role table, no score, a threshold scale over the table perhaps later once real tables have been studied. The library says why two names are or are not consistent; callers combine that with their own evidence and set their own thresholds.
  - Decided: symmetric, and direction read off the table: one name is a less specific writing of another when no role has it carrying more.
  - Decided: keys follow the accepted outcomes (option B), one settings object for keys and check, made from a `Parser` so a string is parsed under the caller's configuration and listed spellings come from the parser's `Lexicon`. Every outcome the check forgives coarsens the key: the default gives `family word;given initial`, one key per family word because `part-of-other` is in the default and sources cut surname lists short (`… DE MELO SCHMITT` / `… DE MELO SCHMITT E BRAGA` in tse-donors), an accepted cost of several keys for a name of several family words.
  - Decided: the default is the writing variants, the level OpenAlex, uwcourses and Palace each built by hand. A family name written as an initial is opt-in: its key, the family initial alone, makes very large groups.
  - Decided: minimum evidence, the family role filled on both sides and agreeing (any accepted outcome but one-sided). A missing given name is opt-in, because under the key guarantee it makes every name with that surname emit a bare surname key. Middle, suffix and title may be one-sided. Accepted cost: a name with no family name (`Suharto`, read as given by default under rules/O5) is consistent with nothing under the default and has no key; a source of such names is handled per source, by `Policy.lone_name_word`, `other-reading`, `given-one-side` or the caller's own handling.
  - Decided: a generation on one side only is consistent and is its own outcome, `generation-one-side`, so a caller can reject father-and-son pairs (`John Smith` / `John Smith Jr.`) in one line; sources drop suffixes for the same person (PatentsView files one inventor as both `Brychell` and `Brychell, III`). A different generation conflicts; a credential and a title never do, only noted.
  - Decided: cross-role matches (a middle name used as given, a nickname used as given, a birth name used as family) are an opt-in outcome, `across-roles`, naming both roles in `MatchResult.across`.
  - Decided (after the builder check, the designer's calls): `part-of-other` compares family to family only, reaching into the other side's middle role being a cross-role match; a hyphenated family name is split on the hyphen for `part-of-other` and for keys (`Smith-Jones` keys `smith`, `jones` and `smithjones`, following OpenAlex's joined-and-split handling); the matcher's own lexicon decides `listed-spelling` for both sides, whatever parsed them; `same_as` defines equivalence classes, two words being a listed spelling of each other when they share a headword; `Jr.` and `II` are not linked; `other-reading` tries one alternative at a time per side, never combinations, and emits keys for each alternative reading so the guarantee holds under it.
  - Implementation call: `J.` / `J` reads `folded`, the stronger outcome, since the fold drops full stops; `initials-agree` covers the same initials differing in spacing or hyphens (`J.-P.` / `J. P.`).
  - Implementation call: the fold drops a combining mark only where its base letter is Latin, Greek or Cyrillic, the scripts whose accents are meant; a mark on another script's letter (a Devanagari virama, anusvara or vowel sign) is spelling and is kept, a false match being worse than a missed one. Accepted cost: some non-Latin accent variants read conflict, and Russian `Й` folds to `И` though Russian treats them as different letters (pinned by a test).
  - Implementation call: keys use each family word's lexicon headword, and the headword's first letter for the given name, so listed spellings share a key; each word is keyed under both its folded form's headword and its headword folded, because either alone loses one class of folded or listed pair.
  - Implementation call: `part-of-other` compares family-base words, particles excluded (setting particles aside is `particles-aside`'s job), so a family of particles alone is never part of a longer one (`Jan Van` / `Jan van der Berg` stays a conflict). Accepted cost: a short family of particles only, likely a truncation, reads conflict.
  - Implementation call: alternative readings are searched only where `other-reading` is accepted; otherwise the table reported is the names as parsed (`Suharto` / `Suharto` reads family conflict under the default), so the default's cost is unchanged and its table is honest. An alternative moving words into the title or suffix, roles that never conflict, is not used, so a word cannot vanish into a noted role to make two given names agree (`Van Gogh` / `Dean Gogh` stays a conflict with `Dean` able to be a title). Accepted cost: a few true matches through a title reading are missed, and the skip covers the suffix too though a generation can conflict there.
  - Implementation call: `across-roles` is searched only where it is accepted, like `other-reading`, and counts only at `same`, `folded` or `listed-spelling`, a full name on both sides, never an initial: the design's three examples are all full names. Accepted cost: `J. Edgar Hoover` / `E. Hoover` reads conflict. A middle word that resolves the given role is consumed, the middle words left compared role to role, one word taking one alignment (`John Edgar Allan Hoover` / `Edgar Allan Hoover` is consistent).
  - Implementation call: `_match` imports `_policy` for the scripts that write no initials (`_NO_INITIALS`, rules/R7), where a single character is a whole word and never an initial, rather than copying the table, as `_render` does.
  - Declined: one settings-free key set covering every outcome (`{"vega", "smith"}`): an unconditional guarantee, but every common surname becomes one enormous group.
  - Declined: keys labelled with the outcomes they serve, for the caller to filter: one call, but it pushes the choosing onto every caller.
  - Declined: typo tolerance (`Slvatore` / `Salvatore` is a conflict; the table names the role, so a caller can run a fuzzy comparison on it alone), transliteration and cross-language inflection, a nickname table beyond the vocabulary's `same_as` (language-specific, opt-in config if ever), and guessing name order inside the check (order is settled per source by the caller's `Policy`).
  - Not in this design: sniffing a source to suggest a `Policy` from a sample of its names, parked to be raised once this has landed; the `order` ambiguity kind stays reserved and unemitted (decisions/D2), so `other-reading` covers the per-token forks reported today, not whole-name order.
