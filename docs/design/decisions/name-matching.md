# name-matching — grouping keys and a consistency check that explains itself

## Standing

- Name matching answers "could these two names be the same person?" with a verdict and a per-role table, never a score: `MatchResult.consistent`, and one `RoleMatch` per `Role` in `Role` order holding the outcome, both sides' text and the side that carried more; consistent means nothing in the two names contradicts the match under the accepted outcomes, not that they name one person — 2026-11-08 #1006.
- One settings object, `Matching`, made from a `Parser` (`Parser.matching(accept=...)`), holds the accepted outcomes, and both `check` and `keys` are its methods, so keys built under one setting are never checked under another; `accept` replaces the default rather than extending it, `same` is always in it and `conflict` never can be — 2026-11-08 #1006.
- The default accepts the writing variants (`same`, `folded`, `listed-spelling`, `particles-aside`, `part-of-other`, `initial`, `initials-agree`, `one-side`, `generation-one-side`, `noted`); `family-initial`, `given-one-side`, `hyphenated-part`, `other-reading` and `across-roles` are opt-in; the first three are reported in the table either way, while `other-reading` and `across-roles` are searched only where accepted, so a setting without them reports the names as parsed (`Suharto` / `Suharto` reads family `conflict` under the default), amending the build's first call, which reported every opt-in either way — 2026-11-08 #1006.
- The family role must be filled on both sides and agree, under every setting: by default a name with no family name is consistent with nothing and has no key, and where `other-reading` is accepted it reaches the others through its family reading (`Suharto` / `Suharto` consistent, key `suharto;`) — 2026-11-08 #1006.
- In the suffix role a generation on one side only reads `generation-one-side` whatever credentials either side carries, credentials reading `noted` only where the generations agree — 2026-11-08 #1006.
- `DEFAULT_ACCEPT` stays private; the default is extended through a matcher, `parser.matching(accept=parser.matching().accept | {...})` — 2026-11-08 #1006.
- The check is symmetric (`check(b, a)` is `check(a, b).mirrored()`) and not transitive; a direction is read off `RoleMatch.more`, never a second call — 2026-11-08 #1006.
- Keys follow the accepted outcomes, with the guarantee that two names the check calls consistent share a key: one `word;g` key per folded family-base word (and each half of a hyphenated one beside its joined form), `g` the given name's first letter, each word under both headword orders — 2026-11-08 #1006.
- The fold drops case, full stops, apostrophes and a combining mark on a Latin, Greek or Cyrillic letter, and keeps a mark on any other script's letter — 2026-11-08 #1006.
- `part-of-other` compares the two family bases, particles excluded, so a family of particles alone is part of nothing — 2026-11-08 #1006.
- `other-reading` is searched only where it is accepted and the names as parsed are not consistent, one ambiguity per side at a time, never into the title or suffix — 2026-11-08 #1006.
- `across-roles` is searched only where it is accepted, counts only a full name on both sides (`same`, `folded`, `listed-spelling`), and consumes the middle word it uses — 2026-11-08 #1006.

Elsewhere: `matches()` and `comparison_key()` stay exact, one casefolded component per field (decisions/comparison-surface, whose Declined line on lenient matching this file's entry supersedes in part).

Open: none in this file.

- **2026-11-08 #1006 — NAME MATCHING IS A VERDICT AND A PER-ROLE TABLE, NEVER A SCORE, WITH GROUPING KEYS THAT FOLLOW THE ACCEPTED OUTCOMES.** Callers who parse many names from several sources to find the same person (OpenAlex's author bylines, NASA ADS's author search, the Palace Project against VIAF, uwcourses' instructors; their code surveyed 2026-11-08) all parse, flatten the result back to a string and compare strings, throwing away the structure the parse found exactly where it is needed. `Parser.matching()` keeps it: `keys()` to group, `check()` to compare a pair role by role. The design was settled with the maintainer in a design session on this date; the calls marked as implementation calls below were made while building it, not by the maintainer. Measured over three same-person sources in the 2026-11-08 measured entry below; the behavior rests on `tests/v2/test_match.py`, whose symmetry and key-guarantee properties run over one shared parsed grid.   - Decided: the default is the writing variants, the level OpenAlex, uwcourses and Palace each built by hand. A family name written as an initial is opt-in: its key, the family initial alone, makes very large groups.

A different generation conflicts; a credential and a title never do, only noted.
