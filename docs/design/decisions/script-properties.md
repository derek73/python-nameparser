# script-properties — one private table of what a script's writing does (#1256)

## Standing

- Whether a script has case for the name-case contrast, whether it writes initials, whether it writes period abbreviations and whether a bare run of its letters with a period is a spelled Latin initial are answered by one private table, `_policy._SCRIPT_PROPERTIES`, one row per script with its reason and source, and every rule that asks one of those four questions reads it — 2026-11-12 #1256, the table.
- The rows are keyed by a private name, never by the public `Script` enum, whose membership says what a caller can key a setting on and settles nothing about case or initials — 2026-11-12 #1256, the table.
- A script with no row has case where Unicode gives it one, writes initials and period abbreviations, and spells no Latin initial out: no column selects its letters, so every reader answers as it does for Latin — 2026-11-12 #1256, the table.
- "Writes initials" (rules/T5's veto, rules/R7's `initials()`, the name match, the order report) and "writes period abbreviations" (rules/H2's shape, rules/S3's split and joined shapes) are two columns, which the four East Asian rows answer alike — 2026-11-12 #1256, the table.
- Whether a script writes initials is decided by its writing convention, read where CLDR states one from the locale-authored name patterns that produce an initial, after checking that the locale's block is not a copy of `en`'s; a locale whose `initialPattern` is `{0}`, no period, writes the character itself and no initial — 2026-11-12 #1256, the table. Where the name lists measured contradict CLDR's authored patterns, measured usage decides: CLDR's patterns say how a name may be formatted, and its sample names are made up, not written by the people they name — 2026-11-19 #1149.
- The answer #1191 gave (the Brahmic title-shape veto) is a row, and so is #1223's (Mtavruli repairs to Mkhedruli, read from the Georgian row); #1214 (the Cyrillic apostrophe) and #1224 (a particle opening a hyphenated word) stay in decisions/R4, being questions of a language's spelling that no script column could hold, as the Dutch `IJ` (#1242) is — 2026-11-12 #1256, the table.
- Georgian, Mkhedruli and Mtavruli (U+10D0–10FF, U+1C90–1CBF), has no case for the name-case contrast, read alike by the parse's one-case fact (decisions/S6), the credential lean, the case-repair gate (decisions/R5) and S8's name word behind a credential, and rules/R4's repair writes its first letter in its lower case from the same row; the ecclesiastical Asomtavruli and Nuskhuri, which write initial capitals, are not in the row — 2026-11-12 #1222.
- A Georgian dotted run of single letters is a run of initials, as before: rules/T7's and rules/R3's lower-case run read Unicode's case, Georgian writing its initials in its one case — 2026-11-12 #1222.
- The Myanmar script writes no initials, decided from the writing convention by [#1256's amendment of 2026-11-12](https://github.com/derek73/python-nameparser/issues/1256#issuecomment-6847110959), CLDR's `my` block being `en`'s (every one of its 42 patterns equal to `en`'s once spaces and commas are removed); whether it writes period abbreviations is not decided and reads as before — 2026-11-12 #1234.
- The Thai script writes no initials, decided by the CLDR count (`th` 0 of 20 locale-authored patterns produce one) in the same amendment, and writes period abbreviations, so its titles and degrees written short read as before — 2026-11-12 #1256, Thai.
- The Arabic script (U+0600–06FF, U+0750–077F, U+0870–08FF, U+FB50–FDFF, U+FE70–FEFC, U+10EC0–10EFF) writes no initials and writes period abbreviations: the letters a title is written short with (`د.`, `أ.`, `م.`) are listed as titles, an unlisted letter with a full stop being a name word (`ح. علي`), and `initials()` and the name match give no initial for a word in it. Decided from usage against CLDR's `ar` patterns; the row covers Persian and Urdu too, a row being per script — 2026-11-19 #1149.

- The Lao script (U+0E80–0EFF) writes no initials, decided by the CLDR count (`lo` 0 of 37 locale-authored patterns produce one, its block its own), and writes period abbreviations, so a Lao title written short (`ດຣ.`) reads as before — 2026-11-20 #1380.

  - **Citation practice is consistent with it**, not evidence for it: Arabic-language APA guides give the given name in full in Arabic references (an Al-Azhar University Gaza guide's examples), and users of Zotero and RefWorks report Arabic entries keeping full names where English ones take initials. A web search on 2026-11-19 found no authority stating the convention either way, and nothing on Persian or Urdu.

  - **NFD and the joiners.** T8 counts an Arabic letter's combining marks with it (`_vocab._ARABIC_MARKS`, every mark Unicode names ARABIC) in the gate `_script_segment` asks first, on the chunk and on the name after the stop, so a decomposed `أ.محمد` or `أ.د.أحمد` divides as the composed one does; the first review found the gate left out, a single decomposed `أ.` then swallowing the name into the title. The name after the stop also admits a zero-width non-joiner or joiner between two letters, as Persian spells a name (`د.محمد‌رضا` divides; `Dr.Jean‌Paul` with it). A joiner ending the word or right after the stop is no part of a name, so the word does not divide and reads whole as the listed title, the name with it (`د.محمد‌ رضا` → title 'د.محمد‌'), as `Dr.Jean‌ Smith` read on master: accepted, a case row pinning it. The shape's letter class (`_MARKS`, decisions/H2) still counts no Arabic mark. A vowel mark written on the title letter (`دُ.`) and a presentation form (`ﺩ.`) are not read as the title, and a title written with a vowel (`أَ.د.`) is a title by shape, not the listed one, so it addresses no given name.
