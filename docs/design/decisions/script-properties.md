# script-properties — one private table of what a script's writing does (#1256)

## Standing

- Whether a script has case for the name-case contrast, whether it writes initials, whether it writes period abbreviations and whether a bare run of its letters with a period is a spelled Latin initial are answered by one private table, `_policy._SCRIPT_PROPERTIES`, one row per script with its reason and source, and every rule that asks one of those four questions reads it — 2026-11-12 #1256, the table.
- The rows are keyed by a private name, never by the public `Script` enum, whose membership says what a caller can key a setting on and settles nothing about case or initials — 2026-11-12 #1256, the table.
- A script with no row has case where Unicode gives it one, writes initials and period abbreviations, and spells no Latin initial out: no column selects its letters, so every reader answers as it does for Latin — 2026-11-12 #1256, the table.
- "Writes initials" (rules/T5's veto, rules/R7's `initials()`, the name match, the order report) and "writes period abbreviations" (rules/H2's shape, rules/S3's split and joined shapes) are two columns, which the four East Asian rows answer alike — 2026-11-12 #1256, the table.
- Whether a script writes initials is decided by its writing convention, read where CLDR states one from the locale-authored name patterns that produce an initial, after checking that the locale's block is not a copy of `en`'s; a locale whose `initialPattern` is `{0}`, no period, writes the character itself and no initial — 2026-11-12 #1256, the table.
- The answer #1191 gave (the Brahmic title-shape veto) is a row, and so is #1223's (Mtavruli repairs to Mkhedruli, read from the Georgian row); #1214 (the Cyrillic apostrophe) and #1224 (a particle opening a hyphenated word) stay in decisions/R4, being questions of a language's spelling that no script column could hold, as the Dutch `IJ` (#1242) is — 2026-11-12 #1256, the table.
- Georgian, Mkhedruli and Mtavruli (U+10D0–10FF, U+1C90–1CBF), has no case for the name-case contrast, read alike by the parse's one-case fact (decisions/S6), the credential lean, the case-repair gate (decisions/R5) and S8's name word behind a credential, and rules/R4's repair writes its first letter in its lower case from the same row; the ecclesiastical Asomtavruli and Nuskhuri, which write initial capitals, are not in the row — 2026-11-12 #1222.
- A Georgian dotted run of single letters is a run of initials, as before: rules/T7's and rules/R3's lower-case run read Unicode's case, Georgian writing its initials in its one case — 2026-11-12 #1222.
- The Myanmar script writes no initials, decided on #1256 from the Burmese convention, CLDR's `my` block being a copy of `en`'s; whether it writes period abbreviations is not decided and reads as before — 2026-11-12 #1234.
- The Thai script writes no initials, by CLDR's count (`th` 0 of 20), and writes period abbreviations, so its titles and degrees written short read as before — 2026-11-12 #1256, Thai.

Open: [#1273](https://github.com/derek73/python-nameparser/issues/1273) — what an initial looks like in the Brahmic scripts, the brahmic row's own question (`initials()` gives a vowel sign's base, not the syllable written). [#1274](https://github.com/derek73/python-nameparser/issues/1274) — the Uzbek apostrophe in case repair, a language question beside #1214. [#1242](https://github.com/derek73/python-nameparser/issues/1242) — the Dutch `IJ`, a language question, out of the table by the decision.

Not examined (2026-11-12): the other scripts that write vowel signs on a consonant, Lao, Khmer and Tibetan among them, have no row, and read as Latin does: `ສົມຊາຍ ໃຈດີ`.initials() gives a leading vowel sign as an initial, the defect Thai had. The decision's third column, "joins with vowel signs", was not built: H2's Brahmic Except reads `spells_initials` instead, since Thai joins with vowel signs and must not be vetoed.

Recompute recipe for the CLDR column, as run 2026-11-12 on unicode-org/cldr main c0b65ae3: fetch `common/main/<locale>.xml` for the locale and for `en`; in `personNames`, take every `namePattern` whose text is not the inheritance marker `↑↑↑` (authored) and count those holding `-initial`. Then read the locale's `initialPattern`: where it is `{0}` with no period (zh), the "initial" is the whole character and the locale writes none. Equal in most is not a copy: short patterns (`{given-informal}`, `{title} {surname}`) are written alike in most locales, and `ru`'s block, equal in 36 of 39, is Russian's own.
